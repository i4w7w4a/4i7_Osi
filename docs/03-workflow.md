# Как наполнять

1. Создать issue: вопрос, затронутые P/стороны, известное и неизвестное, ожидаемый результат.
2. Исследование сохранить полностью в разрешённом публичном объёме. Синтез и ограничения держать отдельно. Использовать [шаблон](../templates/research.md).
3. Предложение не занимает ячейку автоматически. Указать альтернативы и условия пересмотра в [решении](../templates/decision.md).
4. После согласования обновить карту и JSON в отдельной ветке; предложить draft PR. Не менять фундамент в обход обсуждения.
5. Проверить ссылки, число адресов, статусы и отсутствие приватного материала. В PR назвать проверки, которые не проводились.
6. Фиксировать версии и принятые изменения в [журнале](../CHANGELOG.md). Слияние — отдельное действие.

Issues — пространство раскрытия; файлы — актуальная видимая карта; PR — проверяемое изменение; Git — история. Пока Wiki и Projects не нужны как второй источник истины. При их появлении они должны ссылаться на эту карту, а не дублировать определения.
